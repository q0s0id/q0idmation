q0lang

q0lang ties code to q0s animation: it computes values, calls functions, and drives frames, named instances, rigs, live physics, particles and lights. One compiler and one virtual machine (qvm) serve q0editor, q0player and the q0shell terminal host.

This reference describes what the current repository implements. What a command does depends on the program running the script: file commands work in q0shell, moving instances and live physics work in q0player.

quick start

Save this as hello.q0lang or hello.q0l; both extensions mean the same plain UTF-8 text. The same file is in examples/hello.q0lang.

q0lang
import q0.math
import q0shell

pb func ease_out t {
  return 1 - (1 - t) ^ 3
}

for i in range(5) {
  progress = i / 4
  x = lerp(0, 100, ease_out(progress))
  q0shell.print! "step", i, "x =", x
}

Run it from the repository root:

powershell
cargo run -p q0shell -- docs/q0lang/examples/hello.q0lang

Output:

text
step 0 x = 0
step 1 x = 57.8125
step 2 x = 87.5
step 3 x = 98.4375
step 4 x = 100

pb func defines a function, return hands back its result, and for walks the numbers from zero to four. Calling a function uses parentheses. A command ending in ! takes its arguments after a space, separated by commas.

code in an animation

A q0rg's general script suits starting values and functions; it runs once when the timeline starts. Frame code runs every time playback enters that frame. Standalone .q0l / .q0lang files join through the project graph; for q0player they have to be part of a bundled export. A symbol (q0rg) placed on the stage that has code of its own gets its own runtime per placed copy, see object scripts.

Put this in a q0rg's general script:

q0lang
import q0.timeline

pb func start_frame {
  return 12
}

gostop! start_frame()

The player jumps to the frame with index 12 and stops; in a shorter animation the index is clamped to the last frame. Frame indices in code start at zero, while the editor numbers frames from one. Do not put an unconditional gostop! 12 into the code of frame 12 itself: the jump runs that frame's code again.

syntax and types

home · libraries · runtime

lines and blocks

One statement takes one line. Blank lines are allowed. # outside quotes starts a comment that runs to the end of the line. Indentation is for readability; braces define the structure.

An opening { ends the header line. A closing } stands on a line of its own; a condition may use } else {. There are no one-line blocks, no semicolons, no multi-line expressions and no // or /* ... */ comments.

q0lang
# a comment
text = "inside a string # stays a character"
do! {
  count = 2
  total = count * 3
}

do! runs its statements right away. It has no scope of its own and no deferred start.

names and assignment

A name starts with a Latin letter or _ and continues with Latin letters, digits and _. Case matters. Host api names join their parts with dots: stage.width, player.x. Non-Latin letters are fine inside strings but not in names.

q0lang
speed = 120
speed = speed + 30
game.score = 0

= stores a value, == compares. There is no separate declaration and no type annotation. +=, -=, ++ and several assignments on one line are not supported. Do not use keywords as names.

game.score is a single name for a shared variable; no game object is created. There is no [] access.

values

typewritten asmeaning
number0, 12, 0.25, -4.5a double-precision number; there is no separate integer type
string"hello", 'hello'UTF-8 text; both quote styles are equivalent
booleantrue, falsealso the result of comparisons and logical operators
nullnullalso what a function returns when it returns nothing

A number starts with a digit: write 0.5, not .5. There is no exponent notation like 1e3, no hexadecimal and no digit separators. Minus is a unary operator.

Strings understand \n, \r, \t, \\, \" and \'. For any other escape the backslash is dropped. For paths, / or \\ is easiest. There is no interpolation and no multi-line literal. The old ..."text" syntax gives a diagnostic.

q0lang
message = "frame " + 12 + "\ndone"
path = "out/report.txt"

An unknown shared name currently evaluates to the internal value ident holding the name's text: copy = missing stores the symbolic missing. It does not become null. A typo in arithmetic therefore usually ends in a type error. Rig and target names are best written in quotes. raw is an internal value left behind by some errors; it has no literal of its own.

operators

From highest to lowest precedence:

leveloperatorsmeaning
1(...), name(...)grouping and calls
2-value, not value, !valuenumeric and logical negation
3^power, grouping from the right
4*, /, %multiply, divide, remainder
5+, -add or join strings, subtract
6<, <=, >, >=ordering
7==, !=equality and inequality
8and, &&logical and
9or, \|\|logical or

Apart from power, binary operators of one level group from the left. Unary minus binds tighter than power: -2 ^ 2 is 4; for -4 write -(2 ^ 2). 2 ^ 3 ^ 2 is 512. There are no bitwise operators.

Arithmetic takes numbers. If either side of + is a string, the other side is turned into text and joined: "2" + 3 gives "23". 2 + true is a type error. / divides with fractions; % behaves like the floating-point remainder. Dividing by zero or leaving a function's domain gives infinity or nan, not an exception.

Equality never converts types: 1 == "1" and 1 == true are false; null == null is true. Ordering compares two numbers or two strings. Strings compare by code point, not by language rules. Write 0 <= x and x <= 1, not 0 <= x <= 1.

false, null, zero, nan and the empty string are falsy. Every other number and every non-empty string is truthy, and so are the internal non-empty ident and raw values.

and / or return true or false and evaluate their right side only when they need it:

q0lang
safe = false and missing_function()
ready = true or missing_function()
within = 0 <= 0.5 and 0.5 <= 1

conditions

q0lang
progress = 0.75
if progress >= 1 {
  state = "done"
} else {
  state = "in progress"
}

else { may also go on the line after }. Instead of else if, put another if inside the else. Blocks do not create scopes.

while

q0lang
count = 0
while count < 4 {
  count = count + 1
}

The condition is checked before every pass. An endless loop is stopped by the instruction limit; it does not continue on the next frame. For animation over time, use frame code.

for and range

q0lang
sum = 0
for i in range(1, 6) {
  sum = sum + i
}
countdown = ""
for n in range(3, 0, -1) {
  countdown = countdown + n
}

sum is 15 and countdown is "321".

headersequence
for i in range(stop) {from 0 up to stop, step 1
for i in range(start, stop) {from start up to stop, step 1
for i in range(start, stop, step) {from start up to stop, step step

stop itself is not included. The arguments are evaluated once, left to right, before the loop. Fractions and negative steps are allowed. A step going the wrong way gives an empty sequence. Bounds and step must be finite numbers, and the step may not be zero.

The counter is shared outside a function and local inside one. After the loop it keeps the last value it was given; an empty loop leaves its previous value alone. Changing the counter in the body does not change the sequence. range only works in a for header; it is not a function that returns an array.

break and continue

q0lang
sum = 0
for i in range(10) {
  if i == 2 {
    continue
  }
  if i == 5 {
    break
  }
  sum = sum + i
}

sum is 8. break leaves the innermost loop. continue moves on to the next pass: for advances its counter by itself, while checks its condition again. Both go on a line of their own and are not allowed outside a loop. A function cannot break or continue the loop of the code that called it.

functions

q0lang
pb func distance x y {
  return sqrt(x * x + y * y)
}
pr func announce value {
  q0shell.print! "distance", value
}
result = distance(3, 4)
announce(result)

pb marks a public function, pr a private one. Parameters in the definition are separated by spaces, without parentheses or commas. Calls need the parentheses and commas. The number of arguments must match exactly; there are no defaults and no variable argument lists.

return value ends the function at once, nested loops included. return without a value, or reaching the end of the body, returns null. return is not allowed outside a function. A call on a line of its own throws its result away.

The form pb func handler target without a body is kept for compatibility: it registers a function that returns null. A do! after it is a block of its own, not its body.

A definition takes effect once execution reaches it, so define a function before its first call. Defining it again replaces it. Recursion works within the limits. Do not name your functions sin, clamp or any other math name: such calls always compile to the built-in.

pb / pr are kept as metadata; both kinds are called by name in the shared runtime. They are not access control and not module scopes. A nested definition also registers a shared name and does not capture the outer function's locals.

scope

Top-level variables live on in one runtime between scripts. Parameters, and every plain name the function body assigns anywhere, are local in the whole body. Nested if, while, for and do! count. Every other name is read from the shared scope.

q0lang
base = 10
pb func offset amount {
  result = base + amount
  return result
}
answer = offset(5)

answer is 15; the locals amount and result do not become shared. If a function assigns base, that base is local; reading it before the assignment is an error, not a read of the shared base.

Dotted names are never local: a function may write game.score or player.x and change the shared variable. A plain shared number is easiest to change through a result: score = add_points(score, 5).

built-in libraries

home · syntax · host api

import name takes exactly one known library name, without quotes. The import is recorded in the runtime. It loads no file, creates no namespace and grants no access to the system. The math functions work without an import. A few imports change how q0player runs the script: import q0.input switches on a game clock that ticks while the timeline is paused, and q0.object, q0.input or q0.mouse in an object script make its frame code run every tick.

start-up order

q0player first creates the shared runtime. The embedded q0lang dependencies of the root project graph run in ascending node id order, then the general script of the entry q0rg, then the code of the first frame. External q0lang dependencies do not run: the player reports that they need a bundled export. If the start-up script already jumped somewhere, the destination's code is not run a second time.

During normal playback, the code of every frame the playhead enters runs. Scripts of one frame run in ascending layer id order, then in stored order. Shared state and defined functions carry over. Frame code of nested q0rgs does not run in the root runtime; a placed symbol with code of its own runs in an object script.

The editor preview runs the general script of the open q0rg and its frame code. Moving the editor's playhead by hand is editing and runs no frame code; seek in the player does run the destination frame's code.

q0.timeline

q0lang
import q0.timeline
start = 3
gorun! start

gorun! target starts playback and jumps to target. gostop! target stops playback and jumps to target. A jump runs the destination's code and skips the frames in between. The command does not end the current script: the whole script runs first, then the host applies the collected actions in order.

Frame indices in code start at zero. A non-negative numeric target becomes a u16: the fraction is dropped and values that are too large saturate at 65535. The host clamps it to the last frame. Use finite whole numbers within the timeline.

A string target like "12" is taken as a numeric index. Named labels like "intro" do not resolve yet. Playback still starts or stops even when the target does not resolve. There is no automatic frame or label variable in the root runtime; inside an object script, frame holds that object's own frame.

An unconditional jump from a frame to itself runs the same code again. The editor and the player stop a chain of jumps after 64 transitions. To stop on a frame without looping, use a flag variable, or put the command in the general script.

q0.input and q0.time

nametypevalue in q0player

input.jump_pressedbooljump went from released to pressed; cleared after the frame's scripts run

import q0.input switches on a game clock that runs independently of the animation's pause button. While a frame is held, its code keeps running at the movie's fps, even in a one-frame project, so controls and movement keep updating with the timeline stopped. Without the import, a paused animation runs no new ticks. On touch screens q0player shows on-screen left, right and jump buttons.

The host refreshes these values before every script. Assigning input.left or time.dt changes neither the keyboard nor the clock, and the next refresh overwrites it. The api offers no other keys, no typed text, no timers and no system time.

Replace name with an instance name given in the project, such as player. The library creates no character by itself. The instance must belong to the current entry q0rg; an unknown name stays an ordinary symbolic identifier.

q0lang
import q0.scene
player.x = player.x + 10

The example needs an instance called player in q0player. Writes to x/y apply after the script ends, as a temporary runtime transform; the project itself never changes. Both values must be finite numbers. Writing width, height or the bounds does not scale the instance: those are measured again.

Within one script, writing player.x does not update player.right; the geometry is measured between runs. Compute limits from the starting bounds plus your own offset, as in the movement recipe.

object scripts

Every placed copy of a symbol (q0rg) that has code of its own, a general script or frame code, gets its own runtime in q0player. Each copy keeps separate variables, its own timeline position and its own handlers, so ten coins can each count their own score. The object's name is its instance name, or Symbol#id when it has none.

  • The symbol's general script runs once when the copy appears on stage.
  • Its frame code runs whenever the copy's own frame changes. With q0.object, q0.input or q0.mouse imported, it runs every tick instead.
  • gorun! and gostop! inside an object script drive that copy's own timeline.
  • Mouse events reach the copy under the pointer, see events.
nameaccessvalue
self.x, self.yread and writeposition within the parent timeline; writing moves the copy

Named instances inside the symbol are reachable as name.x and so on, relative to the copy. q0player runs at most 4096 active objects, and each object run has its own budget of 100,000 instructions.

import q0.object
import q0.mouse

pb func on_click target {
  self.playing = not self.playing
}

listen mouse.click on_click

q0.scene: switching scenes

q0lang
import q0.scene
q0scene.switch! "room_2"

The alias must match the alias of a bundled movie in the root project's graph. An unknown alias gives a diagnostic. This never loads an arbitrary path or opens an outside file.

The player replaces the current scene and starts at frame zero. It drops temporary moves, rig changes, live physics and particles, and refreshes the sound. The shared runtime keeps its variables, functions and imports. Then the new scene's general script and its first frame's code run. The q0lang dependencies of the child scene's graph do not run again, so keep shared logic in the root graph.

q0.particles

The emitters of the particle editor that have "Live" on. An emitter releases nothing until a command tells it to.

q0.light

The lights of the light editor. Lights need no switch to travel: every movie with lights is lit while it plays, and these commands change them on the fly. A light is named by the name given in the light editor.

commanddoes

q0light.darkness! valuehow dark unlit places are, 0 (day) to 1 (pitch dark)

Lights shine on the main timeline's layers up to its light layer; layers above it stay as drawn. A command that changes a light's position, colour, brightness or size takes it over from its keyframes for the rest of the scene. Switching scenes drops every change.

q0lang
import q0.light
import q0.mouse

pb func lights_out target {
  q0light.off! "lamp"
  q0light.darkness! 0.95
}

listen mouse.click lights_out

events

home · host api · functions

listen event handler adds a handler's name to an event's list; xlisten event handler removes it. These are registration statements, without ! and without parentheses. Subscribing the same handler twice keeps one entry; removing a subscription that is not there is fine.

q0lang
import q0.mouse

pb func on_click target {
  q0shell.print! "clicked", target
}

listen mouse.click on_click
xlisten mouse.click on_click

event names

namewhen q0player sends it
mouse.downa button is pressed
mouse.upa button is released
mouse.movethe pointer moves
mouse.clicka press and release
mouse.doublea double click
mouse.wheelthe wheel or a two-finger scroll turns
mouse.overthe pointer enters an object (object scripts only)
mouse.outthe pointer leaves an object (object scripts only)

Another event name gives a parser diagnostic. The runtime stores the names without checking that the handler exists or how many parameters it takes.

delivery in q0player

q0player delivers events to vector v2 movies that import q0.mouse or have object scripts. Each handler is called with one argument, target: "stage" in the movie's shared runtime, the object's name in an object script. On touch screens a tap counts as the mouse.

Before a handler runs, the shared runtime gets these values, in stage coordinates:

namevalue
mouse.x, mouse.ywhere the pointer is
mouse.insidethe pointer is over the stage
mouse.wheel_x, mouse.wheel_yhow far the wheel turned, for mouse.wheel

Object scripts receive events only when they concern them:

  • mouse.down, mouse.double and mouse.wheel go to the object under the pointer.
  • mouse.up goes to the object under the pointer, and to the one the press started on.
  • mouse.click needs the press and the release on the same object.
  • mouse.over and mouse.out are sent when the pointer crosses an object's bounds.

Inside an object script, self.hovered, self.mouse_x and self.mouse_y tell where the pointer is relative to that object. Commands a handler issues are applied right after it, like any script's.

The editor preview and q0shell keep the subscription table but deliver no events. Calling on_click("button") yourself is an ordinary function call, not a mouse event.

Sources: parser catalogue and subscriptions, qvm listener table, player delivery, object delivery, player input.

q0shell: the terminal host for q0lang

q0shell is the third program of the q0idmation family, next to q0player and q0editor. It is a plain terminal host: it runs q0lang files without the editor, computes through the shared runtime and applies q0shell.*! commands to the file system.

running it

powershell
cargo run -p q0shell -- script.q0lang --root .

--root sets the directory that file operations are allowed in. Without --root, the current directory is used.

Short commands need no file:

powershell
cargo run -p q0shell -- -e "q0shell.print! 'hi'" --root .
cargo run -p q0shell -- -e "q0shell.mkdir! 'out'" -e "q0shell.write! 'out/a.txt', 'Q0'" --root .

Each -e / --eval adds one line of q0lang; several -e join into one script. A script path and -e cannot be combined. Timeline, rig, scene, physics and particle commands only print that they are unavailable in q0shell.

commands

q0lang
q0shell.print! "text", 123
q0shell.read! "path.txt"
q0shell.write! "path.txt", "text"
q0shell.append! "path.txt", "more"
q0shell.mkdir! "dir"
q0shell.list! "dir"
q0shell.move! "from.txt", "to.txt"
q0shell.delete! "path.txt"

Every argument is a q0lang expression:

q0lang
import q0.math
import q0shell

slot = round(sin(pi / 2) * 7)
path = "out/" + "slot-" + slot + ".txt"

q0shell.mkdir! "out"
q0shell.write! path, "armed"
q0shell.read! path

print! joins its values with spaces. read! prints the file, list! prints the folder's entries. The longer example in examples/q0shell.q0lang writes, appends, reads, moves and lists files.

safety

q0shell is deliberately low-level, but not blind:

  • absolute paths are refused;
  • .. is refused;
  • deleting the root directory is refused;
  • every operation resolves inside --root.

That covers the first layer of file management: create, write, read, move, delete and list. A movie played in q0player never gets these commands; the player ignores them.

runtime and qvm

home · syntax · host api

from source to effect

source → parser → compiler → qvm bytecode → qvm → host actions → host

The parser turns source into a syntax tree and reports diagnostics with line numbers. The compiler turns the tree into qvm bytecode. qvm runs the bytecode and collects host actions: jumps, commands, rig changes and so on. qvm itself has no access to files, the editor or the player. The host decides which actions it carries out; see the availability table.

The shared runtime lives in q0s-format/src/q0lang/runtime.rs and qvm in q0vm/src/lib.rs. q0editor, q0player and q0shell all run code this way.

runtime state

One runtime keeps, between the scripts it runs:

  • shared variables;
  • imported libraries;
  • event subscriptions;
  • the signatures of public and private functions;
  • the compiled bodies of defined functions, so a function from the general script can be called by later frame code.

q0player keeps one shared runtime per movie and one more per placed copy of a symbol with an object script. Switching scenes keeps the shared runtime. Each runtime caches compiled source: a script that runs on every frame is compiled once.

values

valueholds
numbera 64-bit float; there is no separate integer type
stringUTF-8 text
booltrue or false
nullnothing
identthe text of a name that was never assigned
rawan internal leftover of some errors

The rules for operators, truthiness and conversion are in syntax.

host actions

actionmade byhost
GoRun(target), GoStop(target)gorun!, gostop!editor preview, player

RigSetPosition, RigSetValue, RigReset, RigSetPose, RigResetPoseq0rig.*!player

A target is either a frame index or a label string. Actions are collected while the script runs; the host applies them in order once it ends. Writes to host names such as player.x or self.x are read back the same way, after the script.

diagnostics

Every diagnostic carries the source line it came from. A parse or compile error that makes the program meaningless stops it before it runs. A runtime error, such as a type error, ends that run with a diagnostic; actions collected before it still apply. In q0player, diagnostics are warnings: the movie still opens and plays, and the status line summarises them. q0player keeps at most 256 of them.

limits

limitvalue
instructions per run100,000
instructions per run in the editor's code analysis4,096
operand stack4,096 values
call depth128 nested calls
nested expressions64 levels
nested blocks64 levels
frame and scene jumps in one chain64
active objects with scripts in q0player4,096

A run that hits the instruction limit stops with a diagnostic; an endless while therefore cannot freeze the player. A recursive function shares the budget of the run that called it.

bytecode

qvm bytecode starts with the magic QVM\0 and a version (currently 2), followed by a constant pool, the code and a table of source lines. Encoding is deterministic: the same program always gives the same bytes. Version 1 bytecode still loads. Opcodes 41, 42 and 43 carry the physics, particle and light commands and need a qvm that knows them.

the editor

The q0lang editor window analyses the script being edited with its own small budget. It shows diagnostics, how many statements the script has, the libraries it imports, and a summary of the actions, variables and event subscriptions one run produces. The editor preview runs real frame code; see host api.

Sources: runtime, compiler, qvm, player, object scripts, editor analysis.

recipes

home · host api · events

Short scripts for common jobs. Each one names where it goes: a q0rg's general script, frame code, or a symbol's object script. The instance, emitter and body names are examples; use the names in your project.

shared helpers in the general script

Functions defined in the main timeline's general script stay available to all later frame code.

q0lang
import q0.math

pb func ease_in_out t {
  return t * t * (3 - 2 * t)
}

pb func between a b t {
  return lerp(a, b, ease_in_out(clamp(t, 0, 1)))
}

Frame code can then call between(0, 300, 0.5).

a wobble that runs every tick

In a one-frame movie, import q0.input keeps the frame's code running at the movie's fps. Start the counter in the general script:

q0lang
wobble = 0

and move a logo instance in the frame code:

q0lang
import q0.input
import q0.time
import q0.math
import q0.scene

wobble = wobble + time.dt
logo.y = stage.height / 2 + sin(wobble * 4) * 20

moving a player with the keyboard

Frame code of a held frame. The step is limited by the bounds measured before this run, so the instance stays on the stage.

q0lang
import q0.input
import q0.time
import q0.math
import q0.scene

speed = 240
dx = 0
if input.left {
  dx = dx - speed * time.dt
}
if input.right {
  dx = dx + speed * time.dt
}
dx = clamp(dx, 0 - player.left, stage.width - player.right)
player.x = player.x + dx

a light switch

Frame code of a held frame. Space toggles the room's lamp, and the room goes dark without it.

q0lang
import q0.input
import q0.light

if input.jump_pressed {
  lamp_on = not lamp_on
  if lamp_on {
    q0light.on! "lamp"
    q0light.darkness! 0.4
  } else {
    q0light.off! "lamp"
    q0light.darkness! 0.95
  }
}

Set lamp_on = true in the general script first.

stopping on a frame once

Frame code that jumps once, guarded by a flag so the jump does not repeat itself:

q0lang
import q0.timeline

if not intro_done {
  intro_done = true
  gostop! 0
}

Set intro_done = false in the general script first; an unassigned name is a truthy ident, so not intro_done would be false.
