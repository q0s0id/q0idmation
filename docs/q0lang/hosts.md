# анимация и host api

[главная](README.md) · [библиотеки](builtins.md) · [рецепты](examples.md)

host является программой, которая запускает q0lang и применяет его действия. сам runtime не открывает файлы и не рисует сцену.

## доступность

| возможность | редактор: анализ кода | редактор: preview | q0player v2 | q0shell |
| --- | --- | --- | --- | --- |
| математика, функции, условия, циклы | да, с малым бюджетом | да | да | да |
| общий скрипт и код кадров | анализ отдельного текста | да | да | один входной текст |
| переходы и остановка кадров | только отчёт | да | да | сообщение о недоступности |
| именованные экземпляры, клавиатура, time.dt | host-значений нет | host-значений нет | да | host-значений нет |
| команды рига | только отчёт | не применяются | да | сообщение о недоступности |
| переключение bundled-сцен | только отчёт | не применяется | да | сообщение о недоступности |
| файловые команды | только отчёт | не применяются | игнорируются | да |
| таблица подписок мыши | да | да | да | да |
| автоматический вызов событий мыши | нет | нет | нет | нет |

анализ отдельного скрипта не воспроизводит глобальные переменные, которые появятся после загрузки зависимостей и предыдущих кадров. окончательно проверяй интерактивный проект в q0player. эти возможности относятся к векторному v2-пути; старые bitmap v1 и q0v не исполняют q0lang.

## порядок запуска

в q0player сначала создаётся общий runtime. встроенные q0lang-зависимости корневого графа исполняются по возрастанию id узла, затем общий скрипт entry-q0rg, затем код начального кадра. внешние q0lang-зависимости не исполняются: плеер сообщает о необходимости bundled-экспорта. если начальный скрипт уже сделал переход, код назначения не запускается повторно как дополнительная инициализация.

при обычном воспроизведении код выполняется для каждого пройденного кадра. скрипты одного кадра идут по возрастанию id слоя, при равенстве в порядке хранения. общее состояние и определённые функции сохраняются. код кадров вложенных q0rg автоматически по отдельности не запускается: исполняется текущий entry-q0rg.

в preview редактора запускаются общий скрипт текущего q0rg и его кадры. ручное перемещение по таймлайну редактора служит редактированию и не запускает код кадров; `seek` в плеере запускает код кадра назначения.

## q0.timeline

```q0lang
import q0.timeline
start = 3
gorun! start
```

`gorun! target` включает воспроизведение и переходит к target. `gostop! target` останавливает воспроизведение и переходит к target. переход запускает код назначения, пропуская промежуточные кадры. команда не прекращает текущий скрипт: сначала вычисляется весь скрипт, затем host последовательно применяет накопленные действия.

номера в коде начинаются с нуля. неотрицательный числовой target переводится в u16: дробная часть отбрасывается, слишком большие значения насыщаются до 65535. host ограничивает его последним кадром. используй конечные целые числа в диапазоне таймлайна.

строковый target вроде `"12"` принимается как числовой индекс. произвольные именные метки вроде `"intro"` пока не разрешаются. даже при неразрешённой цели режим воспроизведения меняется. автоматических переменных `frame` и `label` нет: эти имена только перечислены в каталоге библиотеки.

безусловный переход кадра на себя снова запускает тот же код. editor и player ограничивают цепочку переходов бюджетом 64. чтобы остановиться на кадре без повторной петли, используй переменную-флаг либо ставь команду в общий скрипт.

## q0.input и q0.time

| имя | тип | значение в q0player |
| --- | --- | --- |
| `input.left` | bool | удерживается a или стрелка влево |
| `input.right` | bool | удерживается d или стрелка вправо |
| `input.jump` | bool | удерживается w, стрелка вверх или пробел |
| `input.jump_pressed` | bool | обнаружен переход к нажатому jump; сбрасывается после запуска набора скриптов кадра |
| `time.dt` | number | фиксированный шаг в секундах, 1 / fps |

`import q0.input` включает игровой такт, независимый от кнопки паузы анимации. при удержанном кадре его код продолжает выполняться с частотой fps, даже в однокадровом проекте. это позволяет обновлять управление и движение при остановленном таймлайне. без этого импорта остановленная анимация не выполняет новые такты.

host обновляет значения перед каждым скриптом. присваивание `input.left` или `time.dt` не меняет клавиатуру или часы и будет перезаписано синхронизацией. произвольных клавиш, текста клавиатуры, таймеров и текущего системного времени api не предоставляет.

## q0.scene: размеры и экземпляры

| имя | доступ | значение |
| --- | --- | --- |
| `stage.width`, `stage.height` | чтение | размеры сцены в её координатах |
| `name.x`, `name.y` | чтение и запись | перенос именованного экземпляра |
| `name.left`, `name.right`, `name.top`, `name.bottom` | чтение | границы экземпляра в сцене |
| `name.width`, `name.height` | чтение | ширина и высота его границ |

`name` нужно заменить именем экземпляра, назначенным в проекте, например `player`. библиотека не создаёт персонажа автоматически. экземпляр должен принадлежать текущему entry-q0rg; неизвестное имя остаётся обычным символическим идентификатором языка.

```q0lang
import q0.scene
player.x = player.x + 10
```

пример требует экземпляра `player` в q0player. запись x/y применяется после выполнения скрипта как временное преобразование сцены. исходный проект при этом не меняется. оба значения должны быть конечными числами, допустимыми для координат host. запись width/height/границ не масштабирует экземпляр: эти поля вычисляются заново.

внутри того же скрипта запись `player.x` не пересчитывает `player.right`; геометрия обновляется между выполнениями. вычисляй ограничения по исходным границам и своему смещению, как в [примере движения](examples.md).

## q0.scene: переключение сцены

```q0lang
import q0.scene
q0scene.switch! "room_2"
```

alias должен совпадать с alias bundled movie в графе корневого проекта. неизвестный alias выдаёт диагностику. это не загрузка произвольного пути и не открытие внешнего файла.

плеер заменяет текущую сцену, начинает с кадра ноль, сбрасывает временные перемещения и изменения рига, обновляет звук. общий runtime сохраняет переменные, функции и импорты. затем исполняются общий скрипт новой сцены и её начальный кадр. q0lang-зависимости графа дочерней сцены не запускаются повторно: общую логику помещай в корневой граф.

## q0.rig

| команда | действие |
| --- | --- |
| `q0rig.position! control, x, y` | временная позиция контроллера |
| `q0rig.value! control, value` | временное числовое значение контроллера |
| `q0rig.reset! control` | удалить временные position/value данного контроллера |
| `q0rig.pose! pose, weight` | включить сохранённую позу с весом, ограниченным 0…1 |
| `q0rig.pose_reset! pose` | удалить временный вес этой позы |

имена задаются строками; position/value принимают числа. вес позы обязан быть конечным. команды действуют на риг entry-q0rg. контроллер должен быть открыт для runtime через настройку visible in simple; закрытый или отсутствующий контроллер даёт диагностику. у поз проверяется наличие по имени, отдельного требования публичности нет.

```q0lang
import q0.rig
q0rig.position! "look", 40, 25
q0rig.value! "arm blend", 0.75
q0rig.pose! "wave", 0.6
```

это пример для проекта с такими контроллерами и позой. команда сохраняет временное значение; конкретный эффект зависит от привязок рига. `reset` не удаляет авторский контроллер, `pose_reset` не удаляет сохранённую позу. переходы между кадрами сохраняют временные настройки, переключение сцены их сбрасывает.
